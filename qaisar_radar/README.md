# Qaisar US Stocks Radar v1

**Purpose:** U.S. stock signal research, not execution. Separate from the legacy `main.py` application and the pending security PR. No brokerage integration or order placement.

## Pipeline
TradingView US-stock **5-minute** chart -> Pine v6 indicator at **confirmed candle close** -> HTTPS webhook -> FastAPI independently recalculates basic volume/technical filters -> stores JSON result in SQLite -> optional OpenAI Responses API Arabic narrative. The server does not fetch TradingView charts. TradingView pushes calculated values via alerts. One TradingView alert covers symbols only as supported by your TradingView plan; running across a universe requires multiple alerts / a separate data feed.

## Measurements
- Volume: shares **in the 5-minute candle**. Not buy/sell prints or footprint delta.
- RVOL(20): candle volume divided by mean volume of **20 previous candles**, excluding current candle; not time-of-day adjusted.
- Approx dollar turnover: last close * candle shares, *not* actual trade-by-trade dollar turnover.
- VWAP, EMA20/EMA50, RSI14, candle direction and breakout above previous high or below previous low.
- LONG_WATCH: green break above previous bar high, close above VWAP, EMA20 > EMA50, RSI>=50, min volume 100k and RVOL>=1.8.
- SHORT_WATCH: inverse, red break below prior low, below VWAP, EMA20 < EMA50, RSI<=50, min volume 100k and RVOL>=1.8.
- Regular US cash session 9:30am-4:00pm New York time (indicator), *not* extended hours. No guarantee chart volume is comprehensive.

## Setup (do not commit secrets)
Install Python 3.11+:
```bash
pip install -r qaisar_radar/requirements.txt
python -c "import secrets; print(secrets.token_urlsafe(48))"
```
Generate **two separate** random secrets and provide environment variables:
```bash
export QAISAR_WEBHOOK_TOKEN='LONG_RANDOM_VALUE_1'
export QAISAR_ADMIN_TOKEN='DIFFERENT_LONG_RANDOM_VALUE_2'
export QAISAR_AI_ENABLED=false
uvicorn qaisar_radar.app:app --host 0.0.0.0 --port 8000
```
Deploy behind HTTPS on a publicly reachable host using **port 443 or 80**; put the tokens in the host's environment/secret manager. GitHub stores source, **not** the server. TradingView webhook requests have a short timeout; AI generation occurs after the receiver responds using an in-process background task. For reliable delivery at scale use a durable external queue. Keep service private to the extent possible, rate-limit in proxy, restrict inbound networks when feasible, rotate secrets, and backup SQLite. Never reuse the legacy webhook secret. Do not put keys in Pine or alert message.

## TradingView
1. Open a US stock chart (e.g. NASDAQ:NVDA) at **5m** and paste `qaisar_radar/qaisar_radar.pine` in Pine Editor, then Add to chart.
2. Create an alert on **Any alert() function call**, once per bar close.
3. Set **Webhook URL** to `https://YOUR-HOST/radar/webhook/YOUR_RANDOM_QAISAR_WEBHOOK_TOKEN`; TradingView uses 2FA for webhook alerts. **Do not share this URL.**
4. Alert body generated by the script contains no secret. Must keep 5-minute chart, standard US cash market and up-to-date 5-minute OHLCV.
5. Verify server `GET /health` (public), then `GET /radar/events` with header `X-Admin-Token: <admin secret>`.

### Optional OpenAI API (paid usage may apply)
Set `OPENAI_API_KEY` in **server environment only** and `QAISAR_AI_ENABLED=true`. `OPENAI_MODEL` defaults to `gpt-4.1-mini` and can be changed based on provider availability. Reports appear later in `GET /radar/events` (asynchronous in-process). This is **OpenAI API**, not direct access to the current ChatGPT conversation, and a ChatGPT subscription does not automatically pay API usage. With AI disabled all filtering/recording works without external AI fees.
